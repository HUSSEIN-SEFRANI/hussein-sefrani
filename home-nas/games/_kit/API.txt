واجهات السيرفر المتاحة للألعاب (HOME ANAB)
==========================================
اللعبة تُفتح من التلفاز على نفس عنوان السيرفر، فتستطيع أن تنادي هذه الواجهات بـ fetch مباشرة.
خارج التلفاز (مثلاً عند فتح الملف على كمبيوتر) لا تعمل، فعلى اللعبة أن تتجاهل أي خطأ بهدوء.

0) النوع: لعبة أم تعليم؟ (v1.9.6)
   كل تطبيق مجلد في أحد المجلدين المشتركين على السيرفر:
     🎮 «الألعاب»  — للمتعة، بلا نجوم.
     📚 «التعليم»  — درس له بداية ونهاية، وإنهاؤه يعطي نجمة واحدة (ضمن الحد اليومي).
   المجلد هو الذي يقرر. وفي مجلد كل تطبيق ملف app.json يقول نوعه (يكتبه make.sh):
     {"name": "جدول الضرب", "type": "education", "version": 1}      أو  "type": "game"
   يُستعمل لاقتراح المكان، ولتنبيه المدير في لوحة التحكم إن وُضع التطبيق في المجلد الآخر.

1) نجمة إنهاء الدرس (للتطبيقات التعليمية فقط)
   الأسهل مع kit.js:  K.lessonDone("سبب قصير")  → Promise بعدد ما أُضيف (0 أو 1)
     - K.resultScreen يستدعيها وحده مرة واحدة في نهاية كل درس (ويعرض «+1 ⭐ في رصيدك»).
       لشاشة نتيجة ليست نهاية درس: K.resultScreen({ ..., learn: false }).
   أو مباشرة:
   POST /api/tv/stars/earn
   الجسم JSON:  {"amount": 1, "game": "اسم التطبيق", "reason": "السبب (اختياري)"}
   الرد 200:    {"ok": true, "added": 1, "balance": 23, "today": 9, "limit": 20, "capped": false, "learn": true}
     - السيرفر يعرف التطبيق من عنوان الصفحة (/tv/game/<المربع>/<التطبيق>/) ويقرر وحده:
         تطبيق في «التعليم» ← نجمة واحدة مهما كان amount.
         لعبة (في «الألعاب») ← added = 0 دائماً، و learn = false.
     - added قد يكون 0 أيضاً إذا بلغ الطفل الحد اليومي، أو إذا وصل طلب ثانٍ من التطبيق نفسه خلال 20 ثانية
       (نفس الدرس). فاعرض للطفل عدد added لا العدد المطلوب، ولا تعرض شيئاً إذا كان صفراً.
     - استدعِها مرة واحدة عند إنهاء الدرس أو الجولة، لا عند كل إجابة.
     - limit: الحد اليومي لكل شخص من كل التطبيقات التعليمية معاً (الافتراضي 20، يغيّره الأب أو الأم
       من «نجوم العائلة» على الهاتف أو الكمبيوتر؛ 0 = لا نجوم).
   الأخطاء: 400 (عدد غير صالح أو بلا اسم)، 401 (لا يوجد شخص مسجّل على التلفاز)، 403 (ليس من التلفاز).
   كل نجمة تظهر في سجل النجوم: «📚 فلان أنهى درساً ⭐ 1 — اسم التطبيق: السبب».

   مثال (بدون kit.js):
     fetch("/api/tv/stars/earn", { method: "POST", credentials: "same-origin",
       headers: { "Content-Type": "application/json" },
       body: JSON.stringify({ amount: 1, game: "سارة والتفكير", reason: "أنهت المستوى 3" }) })
       .then((r) => (r.ok ? r.json() : null)).then((d) => { if (d && d.added) { /* أظهر +d.added ⭐ */ } }).catch(() => {});

   للتجربة: الخادم التجريبي tools/mock.py يحاكي هذه الواجهة (رصيد 10، حد يومي 20).


2) صور العائلة (من «الأشخاص» في تطبيق الصور: الأشخاص الذين سمّاهم الأهل فقط)
   GET /api/tv/family/people?limit=40&faces=6
   الرد 200:  {"people": [{"id": 12, "name": "جدّو", "faces": [881, 902, 915], "count": 37}, ...]}
     - faces: أرقام وجوه هذا الشخص (الأوضح أولاً). الصور:
         /api/tv/face/<رقم الوجه>          صورة الوجه مربعة (JPEG)، مناسبة لبطاقة «من هذا؟» أو الذاكرة
         /api/tv/face/<رقم الوجه>/photo    الصورة الكاملة التي فيها الوجه، مناسبة للبازل
     - تأتي من صور الطفل نفسه، والمساحة العائلية المشتركة، وصور من اختار «صوري على التلفاز».
     - قد تكون القائمة فارغة (لم يُفعَّل تمييز الوجوه أو لم تُسمَّ الوجوه بعد): اعرض للطفل رسالة لطيفة
       واطلب من الأهل تسمية الأشخاص في تطبيق «الصور» ← «الأشخاص»، أو استعمل بديل اللعبة (مثل مجلد family).
   الأخطاء: 401 (لا يوجد شخص مسجّل على التلفاز)، 403 (ليس من التلفاز)، 404 (وجه غير مسموح).

   مثال:
     const r = await fetch("/api/tv/family/people", { credentials: "same-origin" }).catch(() => null);
     const people = r && r.ok ? (await r.json()).people : [];
     // صورة: `/api/tv/face/${people[0].faces[0]}`

3) نتيجة سؤال تعليمي (لتقرير الأهل الأسبوعي: أين يخطئ الطفل أكثر)
   POST /api/tv/learn/result
   الجسم JSON:  {"game": "جدول الضرب", "topic": "7×8", "ok": false}
     - game: اسم اللعبة. topic: ما سُئل عنه باختصار (الحرف، الكلمة، العملية…)، حتى 80 حرفاً.
     - أرسل واحدة لكل إجابة في الألعاب التعليمية فقط، ولا تنتظر الرد، وتجاهل الأخطاء.
   الرد 200:  {"ok": true}

   للتجربة: tools/mock.py يحاكي 2) بوجوه مرسومة (أو صور في tools/faces/<الاسم>/)، ويطبع 3).

4) أيادي التحكم (البند 49)
   K.pads()     الأيادي الموصولة بترتيب اللاعبين: [0] = اللاعب 1 = «اليد الأساسية» المختارة في التلفاز
                (الإعدادات ← يد التحكم ← «اختيار اليد الأساسية»)، ثم الباقي حسب أول ضغطة.
   K.mainPad()  اليد الأساسية فقط (أو null). قوائم kit تتحرك بها وحدها.
   في لعبة لشخصين: K.pads()[0] للاعب 1 و K.pads()[1] للاعب 2. لا تستعمل navigator.getGamepads() مباشرة.

4ب) الأزرار بالموقع لا بالرمز (البند 52) — قاعدة لكل لعبة جديدة
   الرموز تختلف بين الأيادي (بلايستيشن ✕○□△، نينتندو B A Y X، والأيادي غير الأصلية غيرها)، لكن الوظيفة واحدة حسب الموقع.
   في Gamepad API الأرقام بالموقع في كل الأيادي (mapping "standard"):
     buttons[0] الزر السفلي  ← موافق / الفعل الأساسي (قفز، رمي، اختيار)
     buttons[1] الزر الأيمن  ← رجوع / إلغاء / استراحة
     buttons[2] الزر الأيسر  ← فعل إضافي (مثل: الحقيبة، التبديل)
     buttons[3] الزر العلوي  ← فعل إضافي ثانٍ (مثل: القائمة الخاصة، الصنع)
     الأسهم (12–15) والعصا اليسرى (axes[0], axes[1]) ← التوجيه دائماً، في كل الأيادي. لا تجعل لها وظيفة أخرى.
     زر PS/Home (16) ← محجوز للتلفاز: الخروج من اللعبة بعد رسالة تأكيد. لا تستعمله في اللعبة.
   لا تعكس الأزرار حسب نوع اليد. وفي نص المساعدة اذكر الوظيفة مع الموقع (مثلاً «الزر السفلي للقفز»)،
   أو رمز بلايستيشن ومعه الموقع. التلفاز يرسم الأزرار الأربعة كشكل معيّن (◇) فيه الزر المقصود مضيء.

5) حفظ التقدّم (البند 50)
   const save = K.store("اسم-قصير", { level: 1 });   ثم   save.level = 2; save.save();
   يُحفظ في السيرفر لكل فرد (يدخل في النسخ الاحتياطي ولا يضيع مع إعادة التنصيب)، ونسخة في المتصفح.
   لا تستعمل localStorage مباشرة للتقدّم. الخدمة: GET/PUT /api/tv/save  {"key": "...", "value": {...}} (حتى 256KB).
